# ตรวจและปรับ UX/UI บ่อหลวง GIS

ตรวจเว็บจริงและซอร์สจาก main `d9ae356` วันที่ 15 ตุลาคม 2569 รวมทั้งหน้า FloodDash ภายนอก ขอบเขตงานคือองค์ประกอบนำทาง การจัดกลุ่มชั้นข้อมูล ข้อความ และรูปแบบหน้าสาธารณะ ใช้ระบบ Next/React/Tailwind/Leaflet เดิม

## ข้อสรุป

ปัญหาหลักคือหน้าที่ของเมนูและแผงข้อมูลปะปนกัน ไม่ใช่การมีระบบย่อยมากเกินไป หน้าแรกเป็นพื้นที่ทำงานแผนที่อยู่แล้ว จึงควรคงแผนที่เป็นหน้าหลัก ไม่เพิ่ม landing page อีกชั้นก่อนเข้าถึงข้อมูล

การเปิดชั้นอากาศบนแผนที่และการอ่านอากาศของหมู่บ้านเป็นคนละงาน ควรเก็บทั้งสองความสามารถ แต่ไม่ควรใช้การ์ดเปิดระบบหน้าตาเดียวกับสวิตช์ Layer หรือกระจายลิงก์ปลายทางเดียวกันไปทุกแผง

## สิ่งที่ซ้ำ และการจัดการ

| รายการ | ก่อนปรับ | รูปแบบใหม่ / เหตุผล |
| --- | --- | --- |
| Weather | การ์ดเปิดหน้าในแผงซ้าย และลิงก์ของพื้นที่ในแผงขวา | ตัดการ์ดซ้าย เก็บลิงก์ของพื้นที่ทางขวาเพื่อส่งหมู่บ้าน/พิกัดต่อ |
| Flood Watch | ซ้ำเช่นเดียวกับ Weather | ใช้ลิงก์สถานีรอบพื้นที่ในแผงขวา และเข้าจากเมนูศูนย์สถานการณ์ได้ |
| Dashboard | เมนูหลักและการ์ดในแผง Layer | เหลือเมนูหลัก ใช้ชื่อ “สถิติการแจ้งเหตุ” ให้ต่างจากภาพรวมศูนย์สถานการณ์ |
| Open Data | เมนูหลักและการ์ดในแผง Layer | เหลือเมนูหลัก ใช้ `/open-data` ซึ่งเป็นหน้าสาธารณะ เส้นทางเก่ายังอยู่ |
| เจ้าหน้าที่ | เมนูหลักและ Staff Portal ท้ายแผง | เหลือเมนูหลัก ไม่ปะปนกับการเปิด/ปิดชั้นข้อมูล |
| แจ้งเหตุ | ลิงก์ไปแบบฟอร์มและปุ่มเปิด QR ที่ชื่อชวนเข้าใจว่าเป็นงานเดียวกัน | เก็บ “แจ้งเหตุ” และ “QR แบบฟอร์มแจ้งเหตุ” บนเมนูหลัก แยกการกรอกกับการแชร์ให้ชัด |
| ติดตั้ง PWA | ปุ่มบน desktop กับปุ่มในแผง mobile | เป็นทางเข้าตามขนาดจอ ไม่ใช่ปุ่มซ้ำในมุมมองเดียว เก็บ desktop บนหัวเว็บ และ mobile ในข้อมูลเว็บไซต์ |
| FloodDash | แถวคล้ายสวิตช์ Layer แต่เปิดเว็บภายนอก | เปลี่ยนเป็นลิงก์จริง เปิดแท็บใหม่ มีไอคอนเส้นและบอกว่าเป็นระบบอิสระ |
| ชื่อศูนย์สถานการณ์ในแถบนำทางและลิงก์กลับใน header Weather | เป็นทางกลับภาพรวมซ้ำในตำแหน่งใกล้กัน | ชื่อแบรนด์เป็นข้อความ เมนูภาพรวมเป็นลิงก์หลัก ตัดปุ่มกลับภาพรวมที่ซ้ำใน header |

การมีเมนูอากาศ/น้ำอยู่ในหน้าภาพรวม และลิงก์อากาศ/สถานีของพื้นที่ใน GIS เป็นการซ้ำที่มีประโยชน์: อันแรกเลือกงาน อันหลังส่งบริบทหมู่บ้าน ไม่ควรตัดลิงก์ตามบริบทออกจนผู้ใช้ต้องค้นพิกัดใหม่

## ตำแหน่งที่ควรมี

- **เมนูหลัก**: แผนที่ ศูนย์สถานการณ์ แจ้งเหตุ สถิติการแจ้งเหตุ ข้อมูลเปิด เจ้าหน้าที่ และปุ่มแชร์ QR ที่ระบุหน้าที่ชัด
- **แผงขวา**: เลือกหมู่บ้านจริง 13 หมู่บ้าน ลิงก์รายละเอียดของพื้นที่ ชุดชั้นข้อมูล ค้นหาสถานที่ ชั้นรายงาน ภัย ขอบเขต/แผนที่ฐาน และหลักฐานเพิ่มเติมที่ยุบไว้
- **แผงซ้าย “ชั้นอากาศและน้ำ”**: สวิตช์อากาศ ฝนแบบจำลอง PM2.5 สถานีน้ำและฝน ส่วนข้อมูลแหล่งอ้างอิงเป็นรายละเอียดรอง
- **Weather Center**: สถานะแหล่งข้อมูล เวลาข้อมูล สรุปฝน 24 ชม./3 ชม. รายชั่วโมง เรดาร์ และ NWP พร้อมข้อจำกัดของแต่ละชุด
- **Flood Watch**: จุดอ้างอิง/รัศมี ตัวกรอง สถานีที่มีเวลาวัด แผนที่ และลิงก์อ้างอิง FloodDash ภายนอก
- **ศูนย์สถานการณ์**: สรุปอ่านเร็วและช่องทางไปดูรายละเอียด หลีกเลี่ยงแสดงรายละเอียดทุกชุดซ้ำกับหน้าระบบย่อย

## สิ่งที่ไม่ควรมีในหน้าตาใหม่

- การ์ดนำทางทั่วไปในแผงที่ตั้งชื่อว่าชั้นข้อมูล
- ลิงก์ออกเว็บอื่นที่หน้าตาเหมือน toggle
- ภาษาโฆษณาว่า “แจ้งเตือนน้ำป่าและดินถล่ม” ในคำอธิบายหน้า หากจริงเป็นข้อมูลประกอบการเฝ้าระวัง
- การแสดง FloodDash เป็นแหล่งที่ป้อน Layer ในแผนที่ เมื่อรายการนั้นเป็นเพียงลิงก์ออก
- ตัวเลขผู้เข้าชม นาฬิกาวินาที แสงเรือง gradient เงาหนัก หรือบอลลูนทักทายที่แย่งความสนใจจากข้อมูลพื้นที่
- Emoji ในชุดหน้าที่ปรับ และการใช้สีเพียงอย่างเดียวแทนคำอธิบายสถานะ
- ชื่อ Endpoint ภายในบนหน้าจอสถานีสำหรับประชาชน เก็บชื่อหน่วยงาน ประเภทข้อมูล และสถานะที่มีประโยชน์ต่อการอ่านแทน

## บทบาท FloodDash

หน้า `flood.nonarkara.org/BoLuang` เป็นเว็บ SLIC FloodDash ซึ่งระบุว่าระบบอิสระและไม่ใช่คำเตือนทางการ มีภาพรวมสถานการณ์ระดับประเทศและข้อมูลหลายแหล่ง จึงไม่ควรนำมาเรียกเป็น Layer ของเทศบาลหรือรวมเข้ากับระดับความเสี่ยงภายในด้วยการเปลี่ยน UI

เก็บเป็นแหล่งตรวจสอบเพิ่มเติมทั้งในรายละเอียดแหล่งข้อมูลของแผนที่และหน้า Flood Watch ซึ่งเป็นบริบทน้ำโดยตรง ใช้ URL เดิมพร้อม query เดิมและ `target="_blank" rel="noopener noreferrer"` ไม่เพิ่ม iframe หรือ pipeline ใหม่ การมี path/query ชื่อ BoLuang ไม่เพียงพอจะรับรองว่าข้อมูลทุกชุดของเว็บภายนอกกรองตามขอบเขตเทศบาลเดียวกันแล้ว

## รูปแบบที่นำมาใช้

พื้นขาว/เทาอ่อน เส้นขอบสีอ่อน ตัวอักษรเข้ม ไอคอน SVG เส้น และน้ำหนักตัวอักษรลดลง สีสถานะยังแยกประเภทเดิม สัญลักษณ์บนแผนที่ใช้เส้นหรือข้อความที่อ่านได้แทน Emoji ไม่เปลี่ยนสี polygon เกณฑ์ภัย หรือสีชุดข้อมูลกราฟ

ปุ่มหัวเว็บและตัวเลือกชั้นข้อมูลมีขนาดแตะอย่างน้อย 44px มี focus ring และชื่อสำหรับ screen reader แผงปิดยังใช้ inert เดิม รองรับ reduced motion และมีปุ่มปิดทั้ง desktop/mobile แผงขวาย้ายหลักฐานเพิ่มเติมลงหลังชั้นข้อมูลเพื่อให้เริ่มงานแผนที่ได้ก่อน

## ขอบเขตการเปลี่ยนโค้ด

ปรับเฉพาะ JSX, ข้อความ, ไอคอน, class/CSS และองค์ประกอบนำทางร่วม ใน GIS, Weather, Flood, ศูนย์สถานการณ์, สิ่งแวดล้อม, ผู้บริหาร, สถิติการแจ้งเหตุ, ข้อมูลเปิด และหน้าตาผู้ช่วย AI ใช้ package เดิม ไม่เพิ่ม dependency

ไม่แก้ `app/api`, `lib`, การคำนวณ/threshold, การตรวจ freshness/schema, ช่วงเวลา refresh, การยกเลิกคำขอเก่า, การเลือกพิกัด, geometry, schema/RLS, permission, credentials, monitoring หรือ deployment configuration ฟอร์มรับแจ้งเหตุและหน้าปฏิบัติงานเจ้าหน้าที่ยังคงเดิม งานนี้ไม่ได้เพิ่มระบบแจ้งเตือนจริง การเชื่อมลุ่มน้ำ หรือการยืนยันสถานีใหม่

## การตรวจสอบ

- ชุดทดสอบเดิม 140 รายการผ่านทั้งหมด
- Typecheck และ production build ตรวจหลังเก็บงาน โดย build สร้าง static pages 34 หน้า
- Explicit ESLint ผ่านองค์ประกอบใหม่และหน้าที่เดิมไม่มีข้อผิดพลาด เปรียบเทียบ baseline ของหน้า legacy แล้วไม่มี error/warning เพิ่ม ไม่อ้างว่า lint ทั้งโครงการสะอาด เพราะยังมีข้อผิดพลาดเดิม
- ทดสอบ browser แบบ production: GIS เลือกหมู่ 8 บ้านกิ่วลม → Weather → Flood → GIS ชื่อและพิกัด `18.125255953798934, 98.43819431975496` ส่งต่อครบ
- ทดสอบมือถือ 390 × 844: เปิด/ปิดแผง แผงซ่อนไม่รับการโฟกัส และเปิดอีกแผงแล้วแผงเดิมยุบ ใช้พฤติกรรมเดิม
- แหล่งข้อมูลจริงโหลดได้หลังอนุญาตการเชื่อมต่อเครือข่ายในเครื่อง ไม่ใส่ข้อมูลจำลองเมื่อ upstream ขัดข้อง
- ระหว่างแก้ไฟล์พบ Leaflet hot reload ผิดพลาด จึงตรวจซ้ำด้วย production build ที่ไม่มี HMR การเปลี่ยนหน้าใช้งานได้

ภาพและผลตรวจล่าสุดแนบในงานนี้ ส่วนรายงานนี้เป็นการตรวจ UX/UI ไม่ใช่การรับรองความแม่นยำของข้อมูลภัยพิบัติ
